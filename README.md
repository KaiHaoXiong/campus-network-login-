# campus-network-login

深澜校园网自动认证。Windows 开机后在后台监测，正常联网时不重复登录；校园网认证失效或无线/有线切换后，确认需要认证才弹出窗口重连。

## 直接使用（已有 config.json）

1. 先关闭之前那个一直显示“每 30 秒登录”的旧 CMD 窗口，避免旧进程继续运行。
2. 双击 `start.bat`，启动确认窗口几秒后关闭，监测程序继续在后台运行。
3. 已经能上网：首次显示“连接成功，无需重复登录”，5 秒后关闭该提示窗口。
4. 需要校园网认证：自动弹出重连窗口；成功后 5 秒关闭；失败提示默认保留 15 秒。
5. 双击 `status.bat` 查看后台运行情况；双击 `stop.bat` 停止后台监测和它打开的重连任务。

退出 Codex、关闭启动确认窗口，不影响后台监测。重连窗口成功关闭也不代表后台停止。
不要同时保留旧版循环脚本和新版监测进程；新版的单实例保护只能管理新版进程。

## 安装和配置

- 推荐 Windows 10/11、Python 3.10+。
- 登录与前台监测逻辑可在其他系统运行，弹窗与批处理启动体验以 Windows 为主。
- 安装依赖：`python -m pip install -r requirements.txt`，只有 `requests` 一个第三方依赖。
- 第一次使用：复制 `config.example.json` 为 `config.json`，填写自己的账号、密码及运营商。
- 已有的 `config.json` 不要覆盖，新选项有默认值，旧密码配置继续兼容。

新配置明确指定密码格式：

```json
{
    "username": "你的学号",
    "password": "你的密码",
    "password_encoding": "plain",
    "domain": "@cmcc"
}
```

`domain` 应与实际校园网套餐对应；模板默认 `@cmcc`。其他运营商后缀以学校认证页面为准。

密码是明文时设置 `"password_encoding": "plain"`；已做 Base64 编码时设置 `"password_encoding": "base64"`。
未指定该字段的旧配置按 Base64 处理，与原脚本保持一致，不会猜测或自动改写密码。
Base64 只是可还原的编码，不是密码加密。真实配置被 Git 忽略；日志不记录原始认证响应或请求参数。

## 开机启动

`Win + R` 输入 `shell:startup`，将**项目中的 start.bat 的快捷方式**放入启动文件夹。
只保留一个本项目的启动项。请使用快捷方式，不要复制 `start.bat` 本体到启动文件夹，因为它按自身所在目录查找项目。

如果启动文件夹里已经有旧版 `start.bat`，应将其替换为指向项目 `start.bat` 的快捷方式，或仅调用项目入口的转发脚本。
项目内批处理使用 ASCII 内容、CRLF 换行和脚本所在目录，不依赖原来的 `D:\Project` 路径。

## 怎么判断要不要登录

1. 等待网卡就绪，观察到认证服务器和默认外网的出站地址变化时，等待约 0.8 秒稳定后走快速通道。
2. 快速通道先查询学校网页实际使用的 `/v1/srun_portal_detect` 接口，或重读已观察到的入口页面，并处理 `index_N.html`、HTTP/HTML/JS 的多步跳转。自动读取当前入口和 `ac_id`，明确掉线后不再额外等下一轮 10 秒。
3. 平常的外网检测在独立线程执行，通过**预期状态码和完整内容**判断能否上网，不把登录页、HTTP 重定向或随便一个 200 响应当成联网成功。旧网络的 DNS 请求卡住也不阻塞切网处理。
4. 服务端确认已认证时保留连接，即使外网探测站点暂不可达也不重复登录；状态支持普通 JSON 和 JSONP。
5. 需要认证前还须从校园网服务器取得有效挑战码。未能确认当前入口时，不再拿旧 `ac_id` 提交登录。自动识别只接受配置服务器所在的 `/24` 网段，或 `portal_networks` 显式允许的 IPv4 网段。
6. 平常连续两次需要认证才打开窗口；切网后已明确掉线则省略第二轮。窗口内重新确认入口与出站 IP，不等待域名探测。切网后的过期检测结果丢弃，旧窗口任务取消。
7. 登录请求被服务器接受后立即显示结果，实际外网检查交给后台。抑制同一路径上不明确的“离线”判断；只有后续明确掉线、原本可用的外网失效，或网络切换才重新考虑认证。

无线与有线可能使用不同入口和 `ac_id`，它们是认证控制器参数，不是错误码。当前已知示例为无线 `10.110.74.99 / 8`、有线页面 `10.110.74.91 / 4`。程序以实际接口和页面为准，已观察到的入口保存在 `.runtime/portal_cache.json`，用于加快查找；使用缓存前仍重新读取页面。
默认 `portal_mode` 为 `auto`。仅在已明确知道固定入口时才可手动设为 `fixed`，直接使用配置的 `portal_host/ac_id`。

浏览器 Cookie 不作为检测依据。Cookie 存在与否并不等于当前电脑仍有校园网访问权限。
外网可用时不需要触碰校园网登录接口；外网不可用且无法确认校园网时，后台等待，不尝试认证。

## 可调选项

在现有 `config.json` 中添加需要更改的选项即可；完整模板见 `config.example.json`。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `check_interval` | 10 | 一次检测结束后，等待多少秒再查联网状态 |
| `route_check_interval` | 1 | 每隔多少秒向系统查询出站地址，不发网络请求 |
| `network_settle_seconds` | 0.8 | 出站地址变化后等待连接稳定的时间 |
| `offline_confirmations` | 2 | 平常连续几次需要认证才弹窗；切网且明确掉线时省略第二次 |
| `request_timeout` | 3 | 普通检测和挑战码请求超时，登录连接超时 |
| `fast_request_timeout` | 1.2 | 切网快速检测时每个请求的超时 |
| `login_timeout` | 10 | 提交登录后的响应等待时间，与快速检测分开 |
| `retry_interval` | 30 | 临时失败后的首次重试间隔，后续按倍数延长 |
| `max_retry_interval` | 300 | 临时失败重试间隔上限 |
| `auth_failure_interval` | 300 | 服务器拒绝认证后的等待时间 |
| `success_display_seconds` | 5 | 成功提示窗口保留时间 |
| `failure_display_seconds` | 15 | 失败提示窗口保留时间 |
| `connectivity_checks` | 模板中的两个站点 | 预期内容检测；任意一个符合预期即视为外网可用 |

切网快速通道不等待外网域名探测或固定的第二轮间隔；跳转和状态接口正常响应时可在几秒内启动弹窗，但真实耗时还包括网卡就绪、服务器响应及认证耗时，不能保证掉线瞬间连接成功。
网络没有切换时仍使用周期检测和失败复查。后台最多两个检测线程，不会因为 DNS 挂起而无限创建线程。
仅网络路径查询和状态检测会周期性执行，不会每隔 10 秒或 30 秒提交登录。

配置保存后后台会自动重新加载。修改账号/密码后建议先停止再启动，便于查看首次认证结果。

## 加密兼容性

已核对用户于 2026-10-30 保存的学校实际 `Portal.js` 与 `all.min.js`：`md5(password, token)` 实际为 **HMAC-MD5(token, password)**，不是普通的 MD5(token + password)。原脚本和原对比工具都错误实现为拼接 MD5，现在已修正。
默认 `"encryption_mode": "legacy"` 对应学校原始代码的 XXTEA 运算分组；用户信息按浏览器 `JSON.stringify` 格式生成，修正中文字符的转义差异。
原 Python 与原 JS 对比文件在“加法和异或的括号位置”上不一致，确实是两种不同的运算。
原 JS 的运算单独命名为 `portal_js`，保留为显式可选模式；不会自动切换算法或连续尝试两份密码认证。
两种模式现在都可与独立 JS 实现自动比较，包含中文及表情字符，修正了 UTF-16 字符处理差异。
已直接提取保存页面中的数学函数，用虚拟机隔离运行，不执行 DOM、网络或登录逻辑；4 组示例的密码摘要、加密信息、校验和均与 Python 一致，并已通过本机校园网实际登录验证。其他学校仍应核对自己的认证页面，现有用户无需更改加密模式。

## 日志和命令

运行状态在 `.runtime/status.json`，监测日志在 `.runtime/monitor.log`，认证详情在 `.runtime/login.log`。
监测日志最多保留三个约 512 KB 的文件，认证日志最多两个，不会无限增长。
认证日志记录选用的入口、`ac_id`、阶段、HTTP 状态、异常类型及耗时，不记录密码、挑战码或含认证参数的完整 URL。窗口会区分“确认客户端地址”“获取认证挑战码”“提交登录”的超时或连接错误，不再统一解释为网络不稳定。
`.runtime` 不会提交到 Git。后台正常联网时不反复刷日志，只记录状态变化和认证结果。

```powershell
python login.py              # 一次检查，必要时登录；结束后退出
python login.py --start      # 后台监测，与 start.bat 一致
python login.py --status     # 查看状态
python login.py --stop       # 停止后台监测
python login.py --loop       # 前台监测，兼容旧命令；Ctrl+C 停止
```

## 校园网实测

实测前关闭旧版循环窗口。先关闭热点并连接校园网，再双击 `start.bat`。

1. 已经能上网时，应提示“连接成功，无需重复登录”，窗口随后关闭；等一两分钟，不应反复弹窗。
2. 校园网未认证时，应在确认后弹窗认证，成功后自动关闭。
3. 从无线切换到有线。如果认证失效，应等待连接稳定后自动弹窗重连；如果仍然能上网，不应重登。
4. 切回热点时，不应向校园网提交认证。
5. 双击 `status.bat` 应显示后台正在运行；双击 `stop.bat` 后再次查看，应显示未运行。

若失败，记录窗口提示和发生时间。回到热点后可查看 `.runtime/monitor.log` 排查，无需重新提供密码。
